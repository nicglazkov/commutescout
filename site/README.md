# CommuteScout site

`site/` holds the commutescout.com marketing and docs pages. It is a
Next.js app built as a static export: `npm run build` writes plain
HTML, CSS and JavaScript to `site/out`. The Python web app
(`src/ca_roads_demo/app.py`) serves those files, so production runs no
Node server. The live map at `/map` is not part of this site; the
Python app serves it from `src/ca_roads_demo/static`.

## Run, lint and build

You need Node 22, the version CI uses. Run these from `site/`:

```sh
npm ci              # install the locked dependencies
npm run dev         # dev server at http://localhost:3000 with hot reload
npm run lint        # ESLint
npx tsc --noEmit    # type check
npm run build       # static export to site/out
```

To see the export the way production serves it, build it, then run the
Python app from the repo root (`ca-roads-demo`) and open the page there.

This version of Next.js has breaking changes from older releases. Read
the guides in `node_modules/next/dist/docs/` before you change routing,
config or data fetching.

## Routes

Each route is one `page.tsx` under `app/`. The export emits one flat
`<page>.html` per route (`trailingSlash: false` in `next.config.ts`),
and `app.py` serves each at a slash-less URL.

| Route | Source | Page |
|---|---|---|
| `/` | `app/page.tsx` | Home |
| `/about` | `app/about/page.tsx` | About |
| `/app` | `app/app/page.tsx` | The phone apps |
| `/contact` | `app/contact/page.tsx` | Contact form |
| `/data-sources` | `app/data-sources/page.tsx` | Data sources and the state coverage matrix |
| `/developers` | `app/developers/page.tsx` | REST API and API keys |
| `/marketplace` | `app/marketplace/page.tsx` | Plugin marketplace |
| `/mcp` | `app/mcp/page.tsx` | Connecting an MCP client |
| `/plugins` | `app/plugins/page.tsx` | Flare, the plugin protocol, and the public catalog |
| `/pricing` | `app/pricing/page.tsx` | Pricing |
| `/privacy` | `app/privacy/page.tsx` | Privacy policy |
| `/terms` | `app/terms/page.tsx` | Terms of service |
| `/sitemap.xml` | `app/sitemap.ts` | Sitemap |

## Where the numbers come from

- **State and feed counts** live in `lib/stats.ts` (`STATE_COUNT` and
  `AGENCY_FEED_COUNT`). `tests/test_snapshot.py` pins them, and the
  same counts in page prose, to the registry in
  `src/ca_roads_demo/states.py`. When coverage changes, update
  `lib/stats.ts` and run that test.
- **The coverage matrix** on `/data-sources` lives in
  `lib/state-coverage.ts`, transcribed from `docs/state-coverage.md`
  and `docs/data-sources.md`. Update it in the same PR as those docs.
  `tests/test_snapshot.py` checks that its row count matches.
- **The API reference** on `/developers`, `lib/api-reference.json`, is
  generated by `scripts/gen_api_reference.py` from the tools' own
  schemas, along with `lib/mcp-clients.json`. Do not edit either file
  by hand. Run the script from the repo root after a tool changes:
  `python scripts/gen_api_reference.py`. `tests/test_api_reference.py`
  fails when the committed JSON is out of date.
